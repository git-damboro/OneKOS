# 千面·OneKOS MVP 演示

千面·OneKOS 是运行在飞书业务环境中的个性化 KOS 内容增长操作系统。本地 MVP 用一条完整证据链展示：Agent 如何认识并持续理解顾问，如何承担选题、写稿、剪辑规划、评论运营和线索筛选，以及如何通过矩阵调度避免上千账号形成“回声室”。

## 启动

双击 `启动演示.bat`，或运行：

```powershell
cd E:\Desktop\BISAI\OneKOS_MVP演示
npm start
```

访问 `http://127.0.0.1:4173/`。

## 七页演示结构

| 页面 | 演示重点 |
|---|---|
| AI 内容工作台 | 一名顾问如何获得机会、选题、创作、质检、评论和线索六类 AI 协作能力 |
| 动态顾问画像 | 10 分钟首次校准、动态标签权重、证据来源、纠偏和持续学习 |
| 机会雷达与选题 | 品牌任务、评论问题、平台趋势和矩阵空白如何形成 1—3 个任务 |
| 内容创作室 | 事实核＋人格壳，交付脚本、分镜、素材、字幕、封面和剪辑时间轴 |
| 矩阵调度与质检 | 事实、合规、人设、矩阵四重质检以及撞题后的空白场景补位 |
| 评论运营中心 | 模拟抖音评论风向、回复建议、风险识别和选题反哺 |
| 线索与策略学习 | 评论字段抽取、线索分级、人工接管和画像权重回流 |

每页右上角均可打开“查看真实实现”，了解正式数据来源、飞书组件、AI 处理逻辑、权限要求、异常处理和人工边界。

## 建议的 3—5 分钟讲解

| 时间 | 操作 | 讲解重点 |
|---|---|---|
| 0:00—0:35 | AI 内容工作台 | OneKOS 不是给顾问增加工作，而是把完整内容流程压缩成补素材、轻改、确认和接管线索 |
| 0:35—1:15 | 动态顾问画像 | 模拟导入 18 条历史内容、60 秒语音和偏好选择，形成有权重、有证据、可纠偏的动态画像 |
| 1:15—1:55 | 机会雷达 | 评论真实问题、顾问优势和矩阵空白共同决定 1—3 个任务，而不是批量改写同一文案 |
| 1:55—2:40 | 内容创作室 | AI 一次性交付脚本、分镜、素材、字幕、封面、剪辑时间轴和评论预案 |
| 2:40—3:25 | 矩阵调度与质检 | 故意触发撞题，展示从措辞去重升级为内容领地重新路由 |
| 3:25—4:15 | 评论运营中心 | 模拟发布后评论回流，AI识别风向、质疑、用户问题和试驾意向 |
| 4:15—5:00 | 线索与策略学习 | 顾问接管 A 级线索，结果反哺“成都本地补能”等标签，下一轮推荐发生变化 |

## 模拟数据原则

- 顾问、门店、评论、互动、矩阵账号和销售线索均为生成的模拟数据；
- 模型使用真实存在的乐道 L60、L90，参数示例来自乐道官网或官方用户手册；
- 品牌知识记录来源、查询日期和有效期；
- 线索字段只能从原评论中提取，不凭空补齐；
- 画像变化必须对应采用、修改、拒绝、互动或线索证据；
- 所有页面显著标注 `SIMULATION`，不会伪装成实时平台数据。

## 正式落地边界

- 飞书 Aily、机器人卡片、多维表格、知识库和工作流承担主要承载；
- 抖音评论与视频数据需申请官方能力并取得账号授权；
- 点赞、评论、分享等字段以正式接口实际返回为准，收藏不作为核心闭环成立的前提；
- CRM 或试驾系统只在企业授权范围内通过 API/Webhook 同步；
- AI 不自动承诺价格权益、不编造顾问经历、不自动触达客户；
- 高风险表达、高意向线索和最终发布均由人工确认。

## 当前版本说明

本轮根据用户要求优先快速生成实现，未执行多轮自动化测试、浏览器截图核对或附件渲染复核。正式提交或现场演示前建议至少运行一次 `npm test` 并人工走通完整链路。
