# OneKOS 3—5 分钟演示手册

## 演示前检查

| 检查项 | 操作 | 通过标准 |
|---|---|---|
| 服务 | `npm start` | 控制台显示地址和 Runtime mode |
| 自动验证 | `npm run check` | 全部测试与 smoke 通过 |
| 运行状态 | 打开“飞书落地中心” | 明确显示 LIVE、HYBRID 或 SIMULATION |
| 数据边界 | 查看顶部和评论页标识 | 抖音与 CRM 明确标注模拟 |

## 演示口播与操作

| 时间 | 页面与操作 | 建议口播 |
|---|---|---|
| 0:00—0:30 | AI 内容工作台 | “OneKOS 不是再给顾问一个复杂工具，而是让 AI 承担机会发现、选题、写稿、剪辑规划、评论和线索筛选。顾问只做四个小决策。” |
| 0:30—1:05 | 动态顾问画像 → 完成校准 | “系统不把顾问固定成某一种类型，而是用带权重、置信度、来源和证据的标签形成动态内容 DNA。新顾问先用资料、历史内容、语音和偏好完成冷启动。” |
| 1:05—1:35 | 机会雷达 → 生成任务 | “一题千解同时看用户问题、品牌任务、顾问画像和矩阵空白，只给当前顾问 1—3 个最匹配任务，避免千号同声。” |
| 1:35—2:15 | 交给创作 Agent | “服务先读取顾问画像、TASK-001 和有效品牌知识，再生成完整内容包。补能事实不足时不编数字，而是明确列出顾问要拍的真实素材。” |
| 2:15—2:50 | 内容创作室 → 四重质检 | “事实核和人格壳分离。服务端再做事实、合规、人设、矩阵四重质检；回声室探测不是改几个词，而是阻止重复角度进入发布。” |
| 2:50—3:20 | 确认模拟发布 | “真实发布仍由顾问确认。这里使用模拟发布和模拟抖音评论，不伪装正式接入。” |
| 3:20—4:10 | 评论运营中心 → 识别销售线索 | “AI 从评论提取城市、家庭、车型、购车时间和试驾意愿，保留字段证据。高意向线索明确进入待顾问人工接管。” |
| 4:10—4:40 | 线索页 → 人工接管 | “只有顾问点击接管并确认反馈后，权重变化才写回画像，形成内容—互动—试驾—成交—策略学习闭环。” |
| 4:40—5:00 | 飞书落地中心 | “多维表格是真实数据底座；Aily 是飞书内入口；Web 服务使用外部兼容模型。两个入口共享数据、规则和人工门禁。” |

## 评委追问时的边界说明

- Aily 当前仅作为飞书内可视化智能体使用，没有对外 API Key；Web 端已改用外部兼容模型。
- 飞书多维表格可通过企业自建应用和 Bitable API 真实读写；没有配置时系统明确进入模拟模式。
- 抖音真实评论接口与 CRM 不在本次授权范围，MVP 使用结构一致、贴近业务的模拟数据。
- 当前 Base 中补能品牌事实不足，因此演示脚本把等待时间、能耗和补能频率保留为实拍后补充。
