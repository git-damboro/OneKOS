## 画像初始化状态机

顾问状态：`uninitialized → collecting → pending_confirmation → active`

会话状态：`draft → generated → confirming → confirmed`；异常状态为 `generation_failed`、`write_failed`。

## 接口索引

所有公开响应不得包含密钥或敏感外部用户标识。

| 方法 | 路径 | 用途 |
|---|---|---|
| `GET` | `/api/advisors` | 列出可选择的顾问 |
| `POST` | `/api/advisors` | 创建 Web 模拟顾问身份 |
| `POST` | `/api/onboarding/sessions` | 创建画像初始化会话 |
| `GET` | `/api/onboarding/sessions/:sessionId` | 恢复初始化进度 |
| `POST` | `/api/onboarding/sessions/:sessionId/generate` | 生成候选画像 |
| `POST` | `/api/onboarding/sessions/:sessionId/confirm` | 确认画像 V1 与首条任务 |

确认接口支持 `Idempotency-Key` 请求头，重复请求返回同一画像版本和任务。

## Web 画像初始化操作

1. 进入“动态顾问画像”，选择已有顾问或使用预填资料创建模拟顾问。
2. 填写基础资料与三组表达偏好；历史内容、语音转写和禁用表达为可选项。
3. 保存后，浏览器在 `localStorage` 记录初始化会话 ID；刷新页面可恢复草稿或候选状态。
4. 生成候选画像后，可编辑标签与权重，也可删除、降低权重或锁定候选。
5. 确认后写入画像 V1 并创建首条内容任务，后续机会雷达和内容生成使用新顾问与新任务 ID。

前端不直接推断标签，候选的来源、证据和置信度均来自初始化服务；服务不可用时明确报错，不伪装为已完成。

## 问卷式初始化与词云画像设计

画像初始化不再使用一次性大表单。已有顾问直接进入问卷；新顾问只填写姓名、城市、门店三个身份字段，然后完成一题一屏的自适应问卷。

- 基础 8 题，根据低置信度或冲突答案追加 2—4 题，整体控制在 3—5 分钟。
- 题型包含选择题、情景判断题和 1 道短文表达题。
- 选择与情景题通过确定性规则生成基础画像词；短文题优先由模型提炼表达词，模型不可用时使用本地规则降级。
- 最终生成 30—50 个词或短语；字号表示权重，颜色表示维度，透明度表示置信度。
- 词语必须保留题目、答案或文本分析证据；同义词合并，无证据词不得进入词云。
- 点击词语可查看来源和证据，并可降权、删除或锁定；锁定词不会被普通行为自动降权。
- 每道答案提交成功后保存进度；浏览器只保存会话 ID，刷新后从服务端恢复当前题目。
- 确认使用幂等键，生成画像 V1 和首条内容任务后进入机会雷达。

核心流程：`选择身份 → 基础问卷 → 自适应追问 → 表达测试 → 候选词云 → 顾问纠偏 → 画像 V1 → 首条任务`。

核心接口调整为：

| 方法 | 路径 | 用途 |
|---|---|---|
| `POST` | `/api/onboarding/quiz-sessions` | 创建问卷会话 |
| `GET` | `/api/onboarding/quiz-sessions/:id` | 恢复问卷进度 |
| `POST` | `/api/onboarding/quiz-sessions/:id/answers` | 提交一道题答案 |
| `POST` | `/api/onboarding/quiz-sessions/:id/complete` | 完成答题并生成候选词 |
| `POST` | `/api/onboarding/quiz-sessions/:id/confirm` | 确认词云画像 V1 |
