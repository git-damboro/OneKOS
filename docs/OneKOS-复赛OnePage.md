## 1. 场景与问题

乐道数千名销售顾问既是销售，也是品牌在社交媒体上最真实的触点。现实中，顾问缺少持续选题、脚本制作、评论运营和线索判断能力；如果直接用生成式 AI 批量写稿，上千账号又容易形成“回声室”，失去平台流量和用户信任。更重要的是，顾问已有接待、跟进和成交流程，新的内容工具如果要求持续填表、学习复杂操作或长时间编辑，最终会被抵触或形式化使用。

因此，问题不是“怎样让 AI 多写稿”，而是同时解决四个冲突：总部事实统一与顾问真实表达、规模生产与账号差异、内容流量与销售归因、系统能力与顾问低负担使用。

| 顾问看不完评论，意向用户被淹没 | AI 聚类风向、提取字段、分级线索，A 级由顾问人工接管 |
| 只看播放量，内容与成交割裂 | 采用、修改、互动、试驾和成交形成反馈事件，更新画像与下一轮策略 |

## 3. 具体方案：Web 与 Aily 双入口＋统一后端＋共享数据

```text
品牌知识 / 顾问证据 / 用户问题 / 矩阵覆盖 / 销售反馈
                         ↓
      飞书多维表格：七张共享业务数据表与流程状态
                         ↕
               OneKOS 统一业务后端
       画像 / 路由 / 内容生成 / 四重质检 / 评论转线索
                 ↙                 ↘
       Web 工作台入口              飞书 Aily 入口
  页面操作完整业务流程       与智能体以对话形式进行查询和发起任务
                 ↘                 ↙
       顾问选择 / 补素材 / 确认 / 接管线索
                         ↓
             反馈写回共享多维表格，更新内容 DNA
```

Web 工作台和飞书 Aily 是面向顾问的两套交互入口，本质上使用同一套 OneKOS 后端能力，并共享同一份飞书多维表格数据。多维表格保存顾问档案、画像标签、品牌知识、内容任务、内容成果、评论线索和反馈事件；统一后端读取结构化证据，完成五类工作：

当前 Web 已能调用 OneKOS 后端展示完整流程；Aily 已能在飞书群中读取共享多维表格。Aily 调用同一后端发起生成和推进流程是下一阶段的发展方向，接通后不会另建一套业务逻辑或数据，而是复用 Web 已有的后端服务和 Base 数据底座。

1. **认识顾问：** 首次使用通过基础资料、10—30 条授权历史内容、60 秒语音转写和少量偏好选择形成画像。标签均包含权重、置信度、来源和证据；顾问可以降低、锁定或删除。
2. **智能选题：** 汇总品牌任务、评论问题、地域场景、顾问优势和矩阵空白，每天只分配 1—3 个任务，并解释为什么推荐、为什么不选其他角度。
3. **生成内容包：** 一次性交付标题、开场、脚本、分镜、素材清单、字幕、封面、剪辑时间轴、评论预案和 CTA。顾问只补 3 段真实素材并做必要轻改。
4. **四重质检：** 同时检查事实、合规、人设和矩阵。回声室探测器从选题、观点、结构、措辞、视觉和 CTA 检测同质化，高风险时不改几个词，而是重新路由到空白场景。
5. **评论转线索：** 从获授权的评论和私信中提取城市、家庭结构、车型、购车时间和试驾意愿，保留逐字段证据并生成等级；高意向由顾问人工接管。

## 4. 销售使用流程

| 阶段 | 顾问操作 | AI 与飞书自动完成 |
|---|---|---|
| 首次校准 | 授权资料、录一段语音、完成少量偏好选择 | 生成可解释动态画像并发确认卡片 |
| 每日选题 | 在卡片中选择一个任务或拒绝 | 路由 1—3 个差异化选题并写入任务表 |
| 内容准备 | 补真实口播、路线或实车镜头，轻改表达 | 生成完整内容包和剪辑时间轴 |
| 发布前 | 确认风险项和最终内容 | 四重质检、矩阵去重、发布门禁 |
| 发布后 | 接管 A 级线索，记录跟进结果 | 评论风向、回复建议、线索评分和策略学习 |

顾问日常只承担四类动作：**选题、补素材、确认、接管线索**，预计投入 8—12 分钟。

### Aily 低负担使用方式

Aily 是 Web 工作台之外的飞书内交互入口，重点解决顾问“找入口、查数据、记流程”的负担。当前已将「千面·OneKOS 内容搭档」加入飞书群，并连接团队共享的飞书多维表格。顾问可以直接在群里 @Aily，使用自然语言查询顾问画像、内容任务、内容成果和评论线索，Aily 读取对应表格记录后返回结果。

本阶段 Aily 主要负责**读取多维表格、解释相关内容等**，内容生成、四重质检和业务闭环仍由现有 Web Demo 展示。下一阶段再将同一套 OneKOS 后端部署为 Aily 可访问的服务，让顾问可以通过聊天发起内容生成、查询执行状态等一系列操作；执行结果仍写回双方共享的飞书多维表格。

## 5. 核心创新与评分对应

| 评分维度 | OneKOS 的证明点 |
|---|---|
| AI 应用创新性 30% | 动态内容 DNA、一题千解、事实核＋人格壳、矩阵级回声室治理，不是统一文案批量改写 |
| 业务价值 30% | 将内容准备压缩为少量决策，并把评论流量转为可跟进线索，以采用率、重复率和合格线索验证 |
| AI 应用深度 20% | Agent 深入“认识顾问—选题—生成—质检—评论—线索—学习”核心链路，输出均写回业务数据 |
| 完整度与推广性 20% | 总部统一知识与规则，区域管理矩阵，顾问保留个性；新增门店只需导入资料、授权和初始化 |

## 6. 价值与验证

| 试点指标 | 目标 | 验证方法 |
|---|---:|---|
| 内容准备时间 | 下降 70% | 对比启用前后从接收任务到发布确认的中位时长 |
| 轻改采用率 | ≥60% | 统计无需重写、仅轻微修改后采用的内容比例 |
| 矩阵近重复率 | <10% | 对选题、语义、结构、视觉和 CTA 形成内容指纹并抽样复核 |
| 合格线索/千次曝光 | 提升 30% | 对比试点组与基线组的 B 级及以上线索数/曝光量 |
| 顾问单日操作负担 | 8—12 分钟 | 记录卡片选择、素材确认和线索接管用时 |

### Aily 读取共享飞书多维表格 Demo

```text
顾问在飞书测试群 @「千面·OneKOS 内容搭档」并提出查询
                              ↓
                     Aily 识别查询意图
                              ↓
       读取已连接的团队共享飞书多维表格中的对应记录
                              ↓
      返回顾问画像、任务、内容成果或评论线索的结构化结果
                              ↓
            在群里解释当前状态并提示顾问下一步动作
```

这条链路当前已经能够现场演示：顾问不用进入 Web 工作台或逐张查看 Base，只需在群里 @Aily 提问，即可获得共享多维表格中的业务数据。飞书多维表格是 Aily 与 OneKOS Web 共用的协作数据底座；Aily 负责群聊查询和解释，Web 负责内容生成、四重质检及完整业务流程展示。

当前边界是：Aily 已能读取共享多维表格，但尚未直接调用 OneKOS Web 后端，因此当前演示是“Aily 群聊查数”和“Web 完整流程”两段能力。后续把后端部署为可安全访问的公网服务后，再由 Aily 从群聊中推动两段链路自动衔接。

当前顾问、抖音互动、线索和销售结果均为贴近真实业务生成的模拟数据；真实实现部分使用可导入的七张多维表格、Aily 五技能提示词、四条工作流和机器人卡片模板。正式落地时，抖音与 CRM 仅在官方能力、账号授权和企业权限范围内接入；AI 不编造事实或顾问经历，不替顾问作价格承诺，不直接触达客户，最终发布与高意向线索均由人工确认。
