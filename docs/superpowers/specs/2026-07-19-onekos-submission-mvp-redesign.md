# 千面·OneKOS 提交材料与 MVP 重构设计规格

## 1. 目标

本次重构把比赛开题文字、附件材料和交互式 MVP 统一为同一条可验证的证据链：

1. Agent 如何以低负担方式认识一名新顾问；
2. 如何通过顾问的采用、修改、拒绝、内容表现和线索结果持续更新动态画像；
3. 如何像一支内容团队一样完成选题、写稿、剪辑规划、评论运营和线索筛选；
4. 如何在总部统一事实的前提下，避免上千账号形成同质化“回声室”；
5. 如何把内容、互动、试驾、成交结果重新反馈给画像和选题策略。

MVP 全部使用生成的模拟数据，但模拟数据必须贴近真实汽车销售与内容运营场景、跨页面因果一致，并在界面明确标识。每个核心能力同时提供“模拟结果”和“真实实现说明”，让评委能够区分演示数据与正式产品能力，并判断方案是否可落地。

## 2. 已确认的设计选择

采用“页面内双层证据式展示”：

- 主层展示顾问正在完成的业务任务和模拟结果，保证 3—5 分钟演示流畅；
- 每个核心页面提供“查看真实实现”入口，展开后说明数据来源、飞书组件、AI 处理逻辑、正式接口、权限要求、异常处理和人工边界；
- 不新增单独的纯技术页面，避免演示链路被割裂；
- 不把技术说明只放在附件中，避免 MVP 被误解为静态概念稿。

## 3. 开题报告文字

### 3.1 Part 1（251 字）

公开案例显示，蔚来已通过总部人设号、区域账号与一线销售构建KOS矩阵，并以创作赋能和分层运营推动线索转化，汽车营销正从单向投放走向真实内容与留资闭环。乐道的难题不只是让AI多写稿，而是同时协调事实统一与真实表达、规模生产与账号差异、流量增长与销售归因。OneKOS以品牌知识库和顾问经历、专长、地域、历史内容及行为反馈形成可解释的动态人设，以低负担卡片交互主动完成选题、脚本和发布建议，让顾问仅补充真实素材并做少量决策；再以效果验证和数据闭环持续优化人设、内容与转化策略，避免内容运营成为销售的新负担。

### 3.2 Part 2（549 字）

我们提出「千面·OneKOS」——运行在飞书中的个性化KOS内容增长操作系统。顾问首次使用时，通过基础资料、授权历史内容、语音样例和少量偏好选择完成快速校准；系统由专业特长、生活身份、地域场景、表达方式、历史作品和编辑行为生成可解释的动态“内容DNA”，并从采用、修改、发布效果及线索结果中持续学习。系统汇总品牌任务、用户问题、平台趋势和本地场景，经“一题千解”路由器每天自动分配1—3个匹配任务；创作Agent交付开场、脚本、分镜、素材清单、字幕、封面、剪辑时间轴、评论预案和转化动作，顾问只需补充真实素材、确认或轻改。生成采用“事实核＋人格壳”：车型参数、权益和政策来自带来源与有效期的品牌知识库，个人表达来自顾问经历及目标用户。发布前执行事实、合规、人设、矩阵四重质检；“回声室探测器”从选题、语义、结构、视觉及转化动作检测近重复，并把拥挤任务调度至空白场景。发布后，AI从获授权的评论、私信及互动指标中识别用户问题、风向和购车意向，生成线索等级与跟进建议，高意向线索由顾问接管并同步CRM。系统以飞书Aily、机器人卡片、多维表格、知识库和工作流承载，试点目标为内容准备时间下降70%、轻改采用率达到60%、近重复率低于10%、合格线索/千次曝光提升30%，验证后可由单店推广至上千名顾问。

## 4. 范围与边界

### 4.1 MVP 范围

- 本地浏览器运行的交互式演示；
- 动态顾问画像、内容机会雷达、脚本与剪辑规划、四重质检、矩阵去重、模拟发布、评论运营、线索识别、结果反馈；
- 贴近真实业务的顾问、内容、评论、互动、知识库、矩阵和线索数据；
- 每项能力的真实实现说明；
- 一键重置并重复演示。

### 4.2 MVP 不包含

- 不读取真实顾问、客户或抖音账号数据；
- 不调用真实抖音、飞书、CRM、试驾系统或大模型服务；
- 不真实发布视频、回复评论、发送私信或触达客户；
- 不承诺平台尚未开放或当前账号未获授权的数据字段；
- 不在 MVP 内实现真正的视频渲染，仅交付可执行的分镜、字幕、素材和剪辑时间轴。

## 5. MVP 信息架构

| 页面 | 核心内容 | 核心操作 | 证明点 |
|---|---|---|---|
| AI 内容工作台 | 今日任务、内容进度、评论待办、高意向线索、节省时间 | 开始今日任务 | 一个顾问拥有一支 AI 内容团队 |
| 动态顾问画像 | 首次校准、标签权重、置信度、证据来源、成长日志 | 确认、纠偏、删除或锁定标签 | Agent 如何认识并持续理解顾问 |
| 机会雷达与智能选题 | 品牌任务、用户问题、平台趋势、本地场景、匹配解释 | 选择 1—3 个任务 | 选题由需求、画像和矩阵空白共同决定 |
| 内容创作室 | 开场、脚本、分镜、素材、字幕、封面、剪辑时间轴、评论预案、CTA | 补充素材、轻改、确认 | 顾问只承担少量决策，而非完整创作 |
| 矩阵调度与四重质检 | 事实、合规、人设、矩阵检查，内容指纹和空白场景 | 修复问题或重新路由 | 解决事实统一与千号同质化冲突 |
| 评论运营中心 | 模拟评论、风向聚类、用户问题、回复建议、风险提示 | 确认回复或加入选题池 | AI 管评论并让评论反哺创作 |
| 线索与策略学习 | 城市、家庭结构、车型、购车时间、试驾意愿、等级、接管状态 | 人工接管并记录结果 | 互动转线索，销售结果反哺画像 |

首次校准作为“动态顾问画像”的首次进入状态，不增加独立导航项。模拟发布作为质检完成后的流程状态，不增加独立页面。

## 6. 动态顾问画像设计

### 6.1 冷启动

首次使用通过约 10 分钟完成四类校准：

1. 顾问填写门店、地域、从业经验、擅长问题和目标客户等基础信息；
2. 在授权前提下导入 10—30 条历史内容；
3. 录入约 60 秒语音样例，用于识别表达节奏、句式和常用语言；
4. 完成少量成对偏好选择，例如“先给结论/先讲故事”“参数证明/场景证明”。

演示中将上述过程压缩为可交互的步骤，不实际上传或分析个人文件。

### 6.2 标签维度

- 专业能力；
- 生活与真实场景；
- 地域经验；
- 表达方式；
- 内容形式；
- 证据偏好；
- 目标用户；
- 转化能力。

不再使用“上海奶爸型顾问”等固定类型名称。每个标签包含权重、置信度、来源、更新时间、状态和证据列表。重复证据、近期行为、有效内容表现及顾问确认会提高权重；长期无证据或效果下降会触发衰减。

### 6.3 四层记忆

| 记忆层 | 内容 | 更新频率 |
|---|---|---|
| 稳定记忆 | 专长、地域、从业经历 | 低频 |
| 表达记忆 | 语言习惯、节奏、结构偏好 | 中频 |
| 兴趣记忆 | 最近关注和愿意创作的主题 | 高频 |
| 效果记忆 | 采用率、互动、线索和成交结果 | 持续更新 |

顾问可以查看“AI 为什么这样判断”，并可降低、删除或锁定标签。系统不推断健康、民族、宗教等敏感属性。

## 7. 模拟数据设计

### 7.1 总体原则

- 所有模拟对象使用稳定 ID，保证内容、评论、线索和反馈能够相互追溯；
- 页面显著标识“模拟演示数据”，不能伪装成实时平台数据；
- 评论语言需要包含口语、省略、质疑、比较、意向和无效互动，不能全部写成结构化问句；
- 播放、点赞、评论、分享和线索数据应处于合理数量级，并保持指标之间的一致性；
- 线索字段只能从原评论或后续模拟对话中抽取，不能凭空补齐；
- 画像权重变化必须对应具体的采用、改写、拒绝、互动或转化证据；
- 矩阵数据同时包含正常差异、轻度重复、严重撞题和未覆盖场景。

### 7.2 顾问样本

MVP 主要展示一名匿名模拟顾问，避免以多个固定人物类型解释个性化。该顾问具有多维标签及不同权重，画像会在完整演示后发生一次可见更新。矩阵页可展示其他匿名账号的内容指纹，但不描述为固定人格类型。

### 7.3 品牌知识样本

示例车型改为真实存在的乐道 L60 和 L90。知识条目包含字段、值、车型版本、来源 URL、发布日期或查询日期、有效期、状态和适用限制。价格、权益等易变信息到期后不可继续作为有效事实。MVP 中采用的品牌事实仅来自乐道官网、官方新闻或官方用户手册。

### 7.4 评论与互动样本

评论覆盖：空间、补能、换电、家庭出行、价格权益、车型对比、试驾预约、产品质疑、内容认可、地域问题和低意向围观。每条评论含模拟用户名、时间、点赞数、所属视频、回复状态和意向信号。点赞、评论、分享等指标用于演示风向判断；收藏可作为明确标识的模拟参考字段，但正式方案不承诺接口一定提供该字段。

### 7.5 线索样本

线索记录保留原评论证据、已识别字段、字段置信度、综合等级、推荐动作和人工接管状态。高意向需要至少出现近期购车或试驾意愿，不能只因评论点赞数高就判断为高意向。

## 8. 核心机制

### 8.1 一题千解路由

路由输入包括品牌任务、用户问题热度、平台趋势、本地场景、顾问标签权重、历史采用行为、矩阵覆盖空白和潜在线索价值。输出 1—3 个任务，并展示采用的画像证据、业务证据和矩阵证据。推荐结果必须能够解释“为什么适合”和“为什么不是其他角度”。

### 8.2 事实核＋人格壳

- 事实核只允许使用知识库中来源有效且未过期的车型参数、权益和政策；
- 人格壳使用顾问的原话、真实经历、表达偏好、地域经验和目标用户；
- 脚本中明确区分事实引用、顾问待补素材和 AI 建议表达；
- 顾问未提供的真实经历不得由 AI 自动编造。

### 8.3 回声室探测

内容指纹由选题、核心观点、叙事结构、关键词与语义、视觉场景、证据类型和 CTA 构成。检测结果分为低、中、高风险。高风险时不只改写措辞，而是重新分配到未覆盖的用户问题、地域场景、内容形式或证据方式。

### 8.4 评论与线索

评论处理先完成主题、情绪、问题、风险和意图识别，再生成回复建议和后续选题。线索模块提取城市、家庭结构、车型、购车时间和试驾意愿，并为每个字段保留证据。高意向线索由顾问人工接管；MVP 不自动联系用户。

### 8.5 策略学习

采用、轻改、重写、拒绝、内容表现、线索质量和成交结果形成反馈事件。事件分别更新表达偏好、近期兴趣、有效内容形式和转化能力，避免单纯用播放量强化泛流量内容。

## 9. “查看真实实现”统一结构

每个页面的说明抽屉包含：

1. 当前模拟了什么；
2. 正式数据来自哪里；
3. 使用哪些飞书或外部系统组件；
4. AI 或规则执行什么处理；
5. 权限、异常和人工接管边界。

说明内容必须具体到组件和数据流，不能只写“接入 AI”或“调用接口”。

## 10. 真实实现可行性映射

| 能力 | 正式实现 |
|---|---|
| 快速校准 | 飞书卡片/表单收集资料，经授权导入历史内容，语音转写形成表达证据 |
| 动态画像 | 多维表格存储标签和证据，Aily 或工作流消费行为事件并更新权重 |
| 品牌知识 | 飞书知识库维护车型事实，检索增强生成，按来源和有效期治理 |
| 自动任务 | 定时工作流汇总品牌任务、问题、趋势和本地场景，路由后用机器人卡片推送 |
| 内容生成 | 大模型生成结构化脚本包，知识检索提供事实，顾问素材作为待补项 |
| 剪辑辅助 | 输出结构化镜头表、字幕、封面和剪辑时间轴；后续可连接模板化剪辑工具 |
| 四重质检 | 知识检索、合规规则、画像相似度和矩阵内容指纹联合判断 |
| 评论管理 | 账号授权并取得抖音互动管理权限后读取评论和提交经确认的回复 |
| 视频指标 | 账号授权后读取抖音开放平台实际提供的视频数据字段 |
| 线索同步 | 飞书工作流通过 CRM/试驾系统 API 或 Webhook 写入获授权字段 |
| 策略学习 | 多维表格记录反馈事件，定时任务更新画像、选题和矩阵覆盖策略 |

飞书 Aily、机器人卡片、多维表格、知识库和工作流承担主要承载；抖音与 CRM 只在官方能力、账号授权和企业权限允许的范围内连接。收藏等字段是否可用取决于平台届时开放能力，不作为核心闭环成立的必要条件。

## 11. 异常处理与人工边界

- 知识来源过期或冲突：停止输出确定性结论，提示总部更新；
- 画像证据不足：降低置信度，以单张卡片请求顾问确认；
- 外部接口中断：展示最后同步时间或缓存状态，不伪造实时结果；
- 高风险表达、价格承诺或负面舆情：必须人工确认；
- 低置信度线索字段：保留为空或标注待确认；
- 高意向线索：仅生成建议和提醒，由顾问人工接管；
- 顾问可查看、删除、降低或锁定画像标签，并可撤回数据授权。

## 13. 演示路径

1. 用压缩流程展示新顾问完成首次校准，生成初始动态画像；
2. 查看标签权重、置信度和证据，进行一次人工纠偏；
3. 汇总品牌任务、评论问题和本地场景，生成 1—3 个选题；
4. 选择任务，生成脚本、分镜、素材、字幕、封面和剪辑时间轴；
5. 触发矩阵撞题，自动切换到内容空白场景；
6. 通过四重质检并模拟发布；
7. 新评论回流，形成风向、回复建议和高意向线索；
8. 顾问人工接管线索，模拟结果反哺画像，使下一次推荐发生变化。

## 14. 验收标准

- Part 1 为 50—300 字，Part 2 为 300—600 字；
- 所有模拟数据均明确标识，跨页面字段和因果关系一致；
- 品牌事实均有来源、版本或查询日期及有效期；
- 每个核心页面均能展开真实实现说明；
- 顾问交互集中为补充素材、轻改、确认和人工接管；
- 选题与脚本明确显示使用了哪些画像、需求和矩阵证据；
- 可触发内容撞题并完成空白场景重新路由；
- 评论可以生成选题、回复建议和可追溯线索；
- 一次完整演示后，顾问画像和下一次推荐发生可解释变化；
- 不把平台未开放、未授权或未实际接入的能力包装成现有实时能力；
- 自动化测试覆盖画像更新、路由、质检、重复检测、评论分析、线索识别和状态重置；
- 本地构建、启动及 3—5 分钟主链路演示通过。
